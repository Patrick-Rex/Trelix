# Trelix 交付里程碑

首版范围为 [产品方案](product-plan.md#首版范围) 中的全部能力，按六个里程碑交付，以验收条件推进，不设置日历交付承诺。本文件维护交付范围、依赖和退出条件，完成结论必须有对应验收证据。

## 阶段与依赖

| 阶段 | 交付范围 | 依赖 | 退出条件 |
| --- | --- | --- | --- |
| M1 工程基础 | 统一构建和依赖配置、按目标结构组织工程、本地编排、前端 TypeScript 工具链 | 无 | 基础工程遵守 [项目结构](architecture.md#目标项目结构) 与依赖方向；前后端联调成功；TypeScript、vue-tsc 与对应检查实际可执行；[AC-01](quality.md#ac-01-工程基础) 通过 |
| M2 存储与认证 | SQLite / EF Core、逻辑模型与迁移、单管理员初始化与会话、防伪造、应用令牌与授权基础 | M1 | 重启后已持久化数据可用；无默认通用密码；管理员登录与退出、身份隔离及令牌生命周期可验证；[AC-02](quality.md#ac-02-认证与凭证)、[AC-03](quality.md#ac-03-持久化) 对本阶段能力的检查通过 |
| M3 配置发布 API | 项目/环境/文件管理、草稿、发布、历史、回滚、并发保护和应用读取 | M2 | API 的规则、错误路径及实际 SQLite 事务可验证；应用仅读取授权范围内的已发布配置；[AC-04](quality.md#ac-04-配置发布)、[AC-05](quality.md#ac-05-并发与事务) 的存储与事务检查，以及 [AC-06](quality.md#ac-06-应用读取与监听) 的读取检查通过 |
| M4 编辑工作区 | 管理员界面、资源树、JSON/YAML/Tree、保存/发布/历史/回滚、应用令牌管理界面 | M3 | 管理员可从界面完成配置发布流程；当前输入、无效数据、切换与并发冲突处理正确；[AC-07](quality.md#ac-07-编辑工作区) 通过 |
| M5 .NET SDK 与监听 | 最低支持 .NET 10 的独立 SDK、单文件接入、长轮询、配置提供程序、失败保留与重载、示例应用 | M3、M4 | 在 .NET 10 示例应用中拉取并监听所选文件；启动失败和运行中恢复行为符合产品规则；配置优先级与重载正确；[AC-05](quality.md#ac-05-并发与事务) 的通知检查、[AC-06](quality.md#ac-06-应用读取与监听)、[AC-08](quality.md#ac-08-net-配置集成) 完整通过 |
| M6 部署验收 | Linux Docker 单容器交付、静态资源集成、SQLite 持久化、备份恢复与完整回归 | M1–M5 | 按 [生产部署](deployment.md) 在目标环境完成交付、容器重建与恢复验证；全部适用验收项通过，操作文档可复现；[AC-09](quality.md#ac-09-生产交付)、[AC-10](quality.md#ac-10-可观测性与信息边界) 通过 |

阶段编号表示交付顺序，跨阶段可以开展不依赖未完成能力的准备工作；准备工作不构成该阶段完成。

## 完成判定

- 每阶段交付包含实现、相应操作说明、验证结果和受影响文档同步。
- 业务实现按目标结构进入 Server 的所属模块，通用技术基础设施进入 Core，宿主默认配置由 ServiceDefaults 维护；依赖方向在 M1 核对，后续阶段持续遵守。测试与被验证行为同阶段接入；SDK、示例和部署资产分别随 M5、M6 交付，不提前创建无内容占位工程。
- 有代码但没有对应验证证据时，不标记里程碑完成。
- M2 的令牌基础验收不能替代 M3 的读取授权或 M5 的长轮询授权验收；功能接入后验证实际入口。
- M3 发布事务和当前发布指向在同一事务内提交；M5 监听只在发布事务成功后观察更新，保存草稿不触发更新。
- M6 完成前，首版所有产品目标、功能验收和文档验收均须满足。构建通过或文档编写完成不能单独构成首版交付。

不以占位测试、零测试结果或无法复现的口头结论作为验收证据。测试工具和执行方式遵循 [质量与验收](quality.md#验证与证据)。
