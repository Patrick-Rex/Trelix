# Trelix UI 设计契约

管理界面沿用现有浅色 IDE 工作区：低饱和绿色主色、灰绿背景、白色内容面、细边框与紧凑工具栏。登录、工作区、令牌页与弹窗使用同一套视觉语言。新增页面延续此基线；视觉风格的整体升级按下述演进流程同步修改，不由单个页面自行换肤。

## 视觉与交互基线

| 维度 | 当前约定 |
| --- | --- |
| 颜色 | 主色为 `--el-color-primary`；正文、辅助信息、错误、警告、成功和背景使用语义变量。危险操作保留明确文字或图标名称，不仅依赖颜色 |
| 排版 | UI 使用系统中文/西文字体，代码与配置预览使用等宽字体；字号由 `--font-size-*` 定义，正文基准 14px，编辑器 13px，标题 22px |
| 形状 | 控件、列表、面板、弹窗各用 `--radius-*` 语义变量；阴影仅用于登录卡、浮动导航与弹窗，使用 `--shadow-*` |
| 布局 | 桌面主导航与资源栏各为 224px，收起导航为 64px；布局宽度由 `--layout-*` 管理。保持顶部上下文、资源树、编辑区、工具栏和底部侧栏开关的职责与位置 |
| 密度 | 沿用现有紧凑工作区；主要间距以 4px 为基础，根据图标、表单和工具栏对齐保留局部调整，不引入独立页面密度体系 |
| 控件 | 优先使用 Element Plus 已接入的表单与弹窗能力；原生按钮复用全局 `.button` 及其状态类，图标沿用 `@element-plus/icons-vue` |
| 状态 | 加载、空数据、失败、无效输入、未保存和禁用状态显式呈现；保存草稿与发布保持不同操作；键盘焦点和操作名称必须可辨识 |
| 窄屏 | 沿用各组件现有断点，导航收起保留图标栏与底部展开入口；工作区可纵向排列，主要操作可换行，无页面级横向溢出 |

## 唯一来源与实现边界

- [theme.css](../src/frontend/src/assets/theme.css) 集中定义颜色、字体、字号、圆角、阴影和公共布局宽度；[main.css](../src/frontend/src/assets/main.css) 负责基础样式、控件和焦点行为。组件的 scoped CSS 仅组合主题变量与局部布局，不另定义主题。
- Element Plus 的主色及色阶在主题入口覆盖；Monaco 通过包装组件固定浅色 `vs` 主题并读取共享的等宽字体和编辑器字号。第三方内部样式由依赖维护，不复制进业务组件。
- `AppShell`、`AppSidebar` 和 `AppHeader` 负责应用布局；资源树、编辑面板、对话框与令牌页组合各自内容。对外使用类型化 props/events，业务规则不依赖组件库内部实现。
- 导入、导出与跨环境复制弹窗共用 [configTransfer.css](../src/frontend/src/features/workspace/components/configTransfer.css)，各组件以 scoped 样式加载，表单布局与视觉规则只维护一份。
- 网站图标与 HTML 的主题色属于静态品牌资产，跟随主题主色同步审查；它们不承担第二套运行时主题定义。
- [契约检查脚本](../src/frontend/scripts/check-contracts.ts) 检查自有模块语言、Vue script 类型和 CSS 中的原始颜色、字号、字体、圆角、阴影及主题变量引用。依赖、生成产物和临时验收资产不在扫描范围；静态检查不能代替布局与可访问性的浏览器验收。

## 验证与演进

实现前明确目标页面、状态、视口与可观察变化；复用既有组件与令牌，功能和性能优先。需要新的视觉语义时在主题入口扩充，并检查已有消费者；整体风格变化先明确目标与契约，已授权的变化直接同步更新本文件、令牌、适配组件和检查规则，不能通过硬编码或关闭检查规避契约。

前端构建执行静态契约检查与类型检查；只读完整检查命令见 [前端 README](../src/frontend/README.md#构建与检查)。界面变更在桌面和手机视口核对布局、主题、焦点、导航开关以及涉及的加载、空白、错误与弹窗状态，编辑器变更还需检查真实 worker 和文本交互。记录实际覆盖范围，不能把静态检查或合成数据预览写成真实 API 验收。业务场景见 [AC-07](quality.md#ac-07-编辑工作区)。
