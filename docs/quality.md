# Trelix 质量与验收

本文把已确认的产品规则与工程约束转成可验证场景。它定义验收要求，不表示检查已经通过；实际验证结论须在交付时提供对应证据。

## 目标与验收映射

| 产品目标 | 验收项 | 主要里程碑 |
| --- | --- | --- |
| G1 统一管理并隔离项目与环境 | AC-02、AC-03、AC-06 | M2、M3、M5 |
| G2 可控发布与可追溯回滚 | AC-04、AC-05、AC-07 | M3、M4 |
| G3 一致且可靠的编辑体验 | AC-07 | M4 |
| G4 接入 .NET 原生配置与重载 | AC-06、AC-08 | M5 |
| G5 独立部署与持久化交付 | AC-01、AC-09、AC-10 | M1、M6 |

目标来源见 [产品目标](product-plan.md#产品目标)。以下检查随对应能力实现，在真实入口上执行。

## AC-01 工程基础

- 统一依赖与 SDK 配置覆盖实际项目；本地启动文档中的项目路径和 Profile 存在。
- 项目遵守目标目录与依赖方向：Server 为单部署宿主并引用 Core、ServiceDefaults；Core 不引用 Server、ServiceDefaults、AppHost 或 SDK；SDK 不引用 Server、Core、ServiceDefaults 或 EF Core，生产项目不引用测试和示例。
- 按 [职责边界](architecture.md#通用技术与业务基础设施边界) 核对代码归属：Core 不含业务类型、DbContext、迁移、权限规则或配置发布通知；Server 按业务模块组织，ServiceDefaults 维护宿主默认配置，通用能力与遥测注册不重复实现。
- AppHost 实际启动前后端，面板链接、HTTPS 和 API 代理可用。
- 业务前端使用 TypeScript 前，类型检查工具和脚本已接入，并能发现类型错误；生产构建不替代类型检查。
- 最小应用壳在开发与生产构建预览中展示侧边栏、顶部栏和主内容空状态；验证侧栏展开/收起、键盘访问及窄屏无横向溢出，未接入业务的占位不得表现为可用操作。
- 构建和其他验证明确各自覆盖范围，未接入的检查不报告通过。

## AC-02 认证与凭证

- 首个管理员由外部初始化凭证创建；已有账号时重启不覆盖；密码不以明文或可还原形式持久化。
- 系统只有一个内置管理员，可管理全部项目与环境；不因目录或接口分组引入额外用户、角色或管理权限模型。
- 管理员登录、退出、会话失效行为正确；管理写请求缺少或使用无效防伪造令牌时被拒绝。
- 固定 8 小时会话不因读取自动续期；退出后重放旧 Cookie 被拒绝，其他会话不受影响；登录也执行防伪造校验，超过来源 IP 限额返回 429。
- 登录 Cookie 使用 HttpOnly，生产环境使用 HTTPS 和 Secure Cookie。
- 应用令牌创建、有效期、撤销、轮换与校验摘要可验证；不能用应用令牌访问管理写接口或草稿。
- 创建令牌必须指定未来有效期及有效的项目/环境组合；支持多范围授权并拒绝错配组合。原文仅在签发时返回，轮换立即废止旧令牌，事务失败不留下部分撤销或新令牌，并发轮换不能产生多个有效后继。
- 认证失败返回 401，身份有效但权限不足返回 403；API 不返回登录页或 SSO 跳转。
- 源码、镜像、URL、日志、错误响应及遥测不包含真实凭证。

## AC-03 持久化

- 以真实 SQLite 验证配置、版本、管理员与令牌授权信息的存取及重启后的可用性。
- 实际映射支持所需版本比较、时间比较及排序；迁移与索引在 SQLite 上可执行。
- 数据库保障项目身份、项目内环境身份、环境内文件名和文件内发布版本的唯一性；当前发布指向、资源层级及令牌授权关联不能跨资源混用。
- 读写与事务行为使用 SQLite 验证，不能仅凭内存替身推断数据库行为。

## AC-04 配置发布

- 不同项目或环境下的同名文件独立管理；服务端拒绝无效 JSON。
- 保存草稿后，应用读取仍为原已发布内容；发布使用明确选中的草稿修订。
- 发布产生不可变历史记录并更新当前指向；历史内容可读取用于管理操作。
- 回滚以历史内容生成新发布版本，历史记录保持不变，当前版本号不倒退。

## AC-05 并发与事务

- 两个调用方从同一基准修改时，过期基准的保存、发布或回滚被拒绝，不能静默覆盖。
- 事务失败时，不留下部分发布内容、版本记录或当前指向变更；监听者不收到成功发布通知。
- 事务成功后读取当前指向可获得对应内容，通知发生在提交之后；保存草稿不发出发布更新。
- 并发基准在实际写入条件中校验；版本分配与发布记录创建受同一事务保护，不能只靠请求开始时的比较或进程内计数。

## AC-06 应用读取与监听

- 分别对读取和长轮询验证：缺少令牌、无效、过期、撤销时返回 401；跨项目或跨环境越权返回 403。
- 所有返回的配置均属于授权范围内的已发布版本，草稿不可通过应用入口获取。
- 成功发布可被监听并读取，草稿保存不触发配置重载；失败发布不产生成功通知。
- 长轮询的超时、取消与重试符合实际契约，客户端停止或切换连接时释放相关请求与后台任务。
- 发布发生在检查版本与注册等待者之间时不会永久漏掉更新；事务提交后通知失败、服务重启和正常超时后均能通过持久化发布身份发现变化。
- 长轮询等待期间不占用数据库事务；唤醒或超时返回前重新检查令牌有效性与权限，已撤销凭证不能读取更新内容。

## AC-07 编辑工作区

- 当前项目、环境和文件清楚可见；管理员可完成登录、退出、资源选择、编辑、保存、发布、历史查看、回滚和应用令牌管理。
- JSON/YAML/Tree 共享数据，转换保持可表示的值与类型；YAML 注释、锚点名称和排版不作为持久化内容。
- 防抖尚未结束或输入无效时立即保存、发布、切换格式，不能提交上一份有效数据；文本缓冲保留当前输入。
- 切换文件或环境处理未保存内容；旧请求返回不会覆盖新文件；并发冲突时保留编辑内容并提示重新核对。
- 在浏览器中检查中文输入法、光标、选择区、滚动、撤销、容器缩放、Monaco worker 路径及卸载后的资源释放。
- 分别检查开发运行和生产构建后的真实页面，覆盖加载中、空数据、校验失败、请求失败、401 与 403 状态。

## AC-08 .NET 配置集成

- SDK 目标框架为 `net10.0`；在 .NET 10 示例应用与测试环境验证首次拉取、监听、配置优先级和重载，覆盖最低支持版本。
- 示例业务应用使用原生 `IConfiguration` 和 Options 消费远程配置，不替换已注册的配置系统。
- 一次接入仅绑定明确的项目、环境和文件；不隐式读取同环境的其他文件，不进行多文件合并。
- 对同名键验证优先级：命令行 > 环境变量 > Trelix > 已启用的 User Secrets > 本地 JSON；本地环境专用 JSON 覆盖通用 JSON。
- SDK 连接信息在首次拉取前可用，远程配置不能改写连接目标或提供自身初始访问令牌。
- 首次拉取及校验在业务配置消费之前完成；超时、无发布内容、认证授权失败或响应无效时启动失败，不静默回退本地配置。
- 运行中断网、监听失败或响应无效时，最近成功配置保持可用；连接恢复后重试获取更新，成功校验后整体替换快照。
- 不产生远程配置磁盘缓存；进程重启重新拉取。重复与乱序响应不会回退有效快照，失败响应不触发清空或部分重载。
- 发布引发提供程序刷新与重载通知；验证 `IOptionsMonitor<T>` 与新作用域 `IOptionsSnapshot<T>` 的更新，不把普通 `IOptions<T>` 或既有连接池当作自动刷新能力。

## AC-09 生产交付

- 在 Linux Docker 目标环境启动单容器，通过统一入口访问静态页面、管理 API 和应用 API；生产运行不依赖 Vite 或 AppHost。
- 容器替换或重建后，从持久化挂载恢复配置、版本、管理员及令牌授权信息，已有管理员不被初始化流程覆盖。
- 按实际交付说明执行备份与恢复；在恢复实例检查已发布配置、版本历史、管理员登录及应用读取。
- 镜像不包含环境专属凭证或真实业务配置；部署参数从外部注入，生产访问使用 HTTPS。
- 发布物和操作说明明确实际配置键、挂载路径、启动方法与恢复步骤，并验证可复现。

## AC-10 可观测性与信息边界

- Server 复用 ServiceDefaults，不重复注册遥测提供程序、instrumentation 或 exporter。
- 故障信息能用于定位操作与结果，同时不泄露原始配置、密码、令牌、Cookie 或连接密钥。
- 健康检查与 OTLP 暴露行为和实际环境一致；不将 Development 专属端点写为生产已具备能力。

## 验证与证据

- 运行与变更行为匹配的最小检查；跨模块行为在实际接口或浏览器中验证。
- 构建仅读取 error 与退出码；测试允许读取失败详情和通过/失败数量，零测试不算通过。
- 执行 .NET 测试前按 [run-tests](../.agents/skills/run-tests/SKILL.md) 识别真实框架与平台；Vue 测试按 [前端指引](../src/frontend/AGENTS.md) 使用实际接入的工具。技能或项目元数据不等于测试框架已接入。
- 每项验证记录对应代码或功能范围、环境、命令或操作、结果与局限；命令输出不是成功的唯一依据。
- 证据不保存敏感配置或凭证；里程碑完成结论链接可追溯的源码与验证记录。

构建与启动命令见 [本地开发](local-development.md)，前端检查命令见 [前端 README](../src/frontend/README.md#构建与检查)。

## 文档验收

- 产品目标、程序边界、技术基线、里程碑与验收要求各有明确主文档，入口可达，无相互矛盾的重复规则。
- 内部文件链接及章节锚点有效；目标结构明确作为实施约束，指向实际文件的链接、已有项目引用、脚本和操作命令与代码一致，不把规划目录写成已存在文件。
- 已确认设计与实际实现分别表述；里程碑完成有对应验证证据。
- 不包含讨论过程、候选方案、未决占位条目或未经用户确认的新规则。
- 修改文件符合 UTF-8 无 BOM、LF、文件末尾换行要求，不产生混合行尾；保留无关文件与用户已有改动。
- 纯文档变更检查内容、来源、链接与格式，不构建业务项目。
